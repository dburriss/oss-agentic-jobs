## Repository tool setup

1. Use `mise --version` to verify mise is installed.
2. Run `mise use dotnet` to set up the local `mise.toml`. This generates the `mise.toml` with the tools.
3. Run `dotnet new tool-manifest` to create a local tool manifest.
4. Run `dotnet tool install OrcAI.Tool` to add OrcAI.Tool to the manifest.

## Mise tasks

Add these tasks to `mise.toml`:

```toml
[tasks.install]
description = "Install tools listed in the manifest."
run = """
dotnet tool restore
"""

[tasks.validate]
description = "Validate all OrcAI job manifests"
depends = ["install"]
run = """
orcai validate "jobs/**/*.yml" --continue-on-error
"""

[tasks.run-jobs]
description = "Run OrcAI jobs after validation"
depends = ["install"]
run = """
orcai run "jobs/**/*.yml" --continue-on-error
"""
```

## Secrets required

Auth setup needs to happen manually unless you have `gh` CLI auth configured for the target org.

Configure these in **Settings → Secrets and variables → Actions → Repository secrets**:

| Secret name              | Description                                          |
|--------------------------|------------------------------------------------------|
| `ORCA_APP_ID`            | GitHub App numeric ID                                |
| `ORCA_APP_INSTALLATION_ID` | Installation ID for the target organisation        |
| `ORCA_APP_PRIVATE_KEY`   | Full PEM content of the App private key (multiline) |

OrcAI reads these env vars directly — no `orcai auth` command is needed in CI.

## Repo setting to enable

**Settings → Actions → General → Workflow permissions**
Set to **"Read and write permissions"** so that `GITHUB_TOKEN` can push the automated lock-file commit back to the repo.

## File 1: `.github/workflows/orcai-verify.yml`

**Purpose:** Validate all job configs on pull requests. Fails the PR check if any YAML is invalid or a referenced repo is inaccessible.

**Trigger:** `pull_request` targeting `main`, path filter `jobs/**`

**Steps:**

1. `actions/checkout@v4`
2. `actions/setup-dotnet@v4` — .NET 10
3. `mise run install` (runs `dotnet tool restore` against `dotnet-tools.json` so `OrcAI.Tool` is available locally)
4. Inject `ORCA_APP_ID`, `ORCA_APP_INSTALLATION_ID`, `ORCA_APP_PRIVATE_KEY` from secrets as env vars
5. `mise run validate` (runs `orcai validate "jobs/**/*.yml" --continue-on-error` only)

**Notes:**

- `--continue-on-error` reports all failures rather than stopping at the first.
- Exit code from `orcai validate` propagates to the workflow step; a non-zero exit fails the PR check.

---

## File 2: `.github/workflows/orcai-run.yml`

**Purpose:** Run all jobs on merge to main. Commits generated lock files back to the repo automatically.

**Trigger:** `push` to `main`, path filter `jobs/**`

**Permissions block (workflow-level):** `contents: write`
Required for `GITHUB_TOKEN` to push the lock-file commit.

**Steps:**

1. **Early-exit guard** — checks `github.event.head_commit.message` for `[skip ci]`; exits with a notice if found. This is belt-and-suspenders on top of GitHub's native `[skip ci]` handling, which should already prevent the workflow from running at all for automated commits. The guard handles any edge cases.
2. `actions/checkout@v4` with `fetch-depth: 0`
   - Full history needed for a clean push after committing lock files.
3. `actions/setup-dotnet@v4` — .NET 10
4. `mise install`
5. Inject `ORCA_APP_ID`, `ORCA_APP_INSTALLATION_ID`, `ORCA_APP_PRIVATE_KEY` from secrets as env vars
6. `mise run validate`
   - Pre-flight check before executing anything. Fails fast if configs are broken.
7. `mise run run-jobs`
   - Creates GitHub Projects, issues, and assigns Copilot across all repos.
   - Writes `<name>.lock.json` alongside each YAML on success.
8. **Detect changed lock files** — `git diff --name-only -- 'jobs/**/*.lock.json'`
9. **Commit and push lock files** (only if step 8 found changes):

```bash
   git config user.name  "github-actions[bot]"
   git config user.email "github-actions[bot]@users.noreply.github.com"
   git add jobs/**/*.lock.json
   git commit -m "[skip ci] chore: update orcai lock files"
   git push
```

   The `[skip ci]` prefix in the commit message prevents this commit from re-triggering the workflow (GitHub Actions natively skips workflows for commits with `[skip ci]` in the message).

---

### Cycle-prevention summary

| Commit type | Triggered by | Contains `[skip ci]`? | Workflow runs? |
|---|---|---|---|
| Normal job-config change | Human | No | Yes — full validate + run |
| Lock-file commit | Actions bot | Yes | No — skipped natively by GitHub |

## OrcAI agent skill

The `.agent/orcai/` skill should teach a companion agent how to:

1. Use the `mise` tasks (`mise install`, `mise run validate`, `mise run run-jobs`) to run command tasks.
2. Authenticate via `orcai auth` when secrets change and refresh tokens as needed.
3. Run `orcai validate` and `orcai run` manually to reproduce CI failures locally.
4. Generate new job YAML/issue template pairs using `orcai generate` and place them under `jobs/<name>/` with the corresponding `.md` issue template references.

Detailed reference documentation for orcai can be found in the [CLI reference](https://github.com/dburriss/orcai/blob/main/docs/cli-reference.md) and the [example repo](https://github.com/dburriss/orcai/tree/main/example).

Skill documentation can be found:
