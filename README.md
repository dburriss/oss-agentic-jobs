# oss-agentic-jobs

GitOps repository for running [OrcAI](https://github.com/dburriss/orcai) jobs across OSS projects.

OrcAI automates the creation of GitHub Projects, issues, and Copilot assignments across many repositories from a single YAML job definition. This repository stores those job definitions and runs them automatically via GitHub Actions.

---

## Repository structure

```text
.github/
  workflows/
    orcai-verify.yml    # validates job configs on every PR touching jobs/
    orcai-run.yml       # runs jobs on every push to main touching jobs/
.agent/
  orcai/
    SKILL.md            # companion agent skill for orcai workflows
jobs/
  <name>/
    <name>.yml          # orcai job config
    <name>.md           # issue template (referenced by the YAML)
    <name>.lock.json    # generated by `orcai run`, committed back automatically
mise.toml               # tool versions and task definitions
dotnet-tools.json       # local .NET tool manifest (includes OrcAI.Tool)
```

---

## Prerequisites

- [mise](https://mise.jdx.dev/) — tool version manager and task runner
- .NET SDK (managed by mise — no manual install needed)

---

## Local setup

```bash
# 1. Restore the .NET tools (including orcai)
mise run install

# 2. Authenticate (GitHub App recommended; PAT also works)
dotnet orcai auth app \
  --app-id <APP_ID> \
  --key /path/to/private-key.pem \
  --installation-id <INSTALLATION_ID>
```

## Creating a new job

Use `orcai generate` to scaffold a job definition and issue template:

```bash
# Interactive — pick repos from a list
dotnet orcai generate --interactive

# Non-interactive
dotnet orcai generate \
  --name "Upgrade to .NET 10" \
  --org my-github-org \
  --repo repo-one \
  --repo repo-two \
  --output jobs/upgrade-dotnet10/upgrade-dotnet10.yml
```

Place both generated files under `jobs/<name>/`, edit the issue template, then validate:

```bash
mise run validate
```

Open a PR — the `orcai-verify` workflow will run validation automatically.

---

## Running jobs locally

```bash
# Validate all job configs
mise run validate

# Run all jobs (creates/updates projects, issues, and Copilot assignments)
mise run run-jobs
```

## GitHub Actions workflows

### `orcai-verify.yml` — PR validation

**Trigger:** `pull_request` targeting `main`, path filter `jobs/**`

Validates all job configs on every pull request that touches `jobs/`. The check fails if any YAML is invalid or a referenced repository is inaccessible. No resources are created or modified.

### `orcai-run.yml` — Main branch execution

**Trigger:** `push` to `main`, path filter `jobs/**`

Runs the full validate-then-execute pipeline on every merge to main. After a successful run, any generated `*.lock.json` files are committed back to the repository automatically using a `[skip ci]` commit to prevent re-triggering the workflow.

| Commit type | Contains `[skip ci]`? | Workflow runs? |
|---|---|---|
| Normal job-config change (human) | No | Yes — full validate + run |
| Lock-file commit (Actions bot) | Yes | No — skipped by GitHub |

## GitHub App authentication setup

The workflows authenticate using a GitHub App. You need to create an app, install it on your organisation, and add the credentials as repository secrets.

### Step-by-step guide

**Step 1 — Create the GitHub App**

1. Go to **GitHub → Settings → Developer settings → GitHub Apps → New GitHub App** (or navigate to your org settings if you want an org-owned app).
2. Fill in the required fields:
   - **GitHub App name:** choose a name, e.g. `orcai-bot`
   - **Homepage URL:** the URL of this repository
   - **Webhook:** uncheck "Active" — no webhook is needed
3. Set the following **Repository permissions**:
   - **Issues:** Read and write
   - **Projects:** Read and write (under "Organization permissions" if creating an org-level app)
   - **Contents:** Read (to read issue templates)
   - **Metadata:** Read (required by default)
4. Under **Where can this GitHub App be installed?**, select **Only on this account** unless you need it cross-org.
5. Click **Create GitHub App**.

**Step 2 — Note the App ID**

On the app's settings page, note the **App ID** (a number). You will need this for `ORCAI_APP_ID`.

**Step 3 — Generate a private key**

1. Scroll to the **Private keys** section on the app settings page.
2. Click **Generate a private key**.
3. A `.pem` file is downloaded. Keep it safe — this is your `ORCAI_APP_PRIVATE_KEY`.

**Step 4 — Install the app on your organisation**

1. On the app settings page, click **Install App** in the sidebar.
2. Choose the organisation (or account) and select which repositories can be accessed (or "All repositories").
3. Click **Install**.

**Step 5 — Note the Installation ID**

After installation, the browser URL will look like:
`https://github.com/organizations/<org>/settings/installations/<INSTALLATION_ID>`

Note the number at the end — this is `ORCAI_APP_INSTALLATION_ID`.

**Step 6 — Add secrets to this repository**

Go to **Settings → Secrets and variables → Actions → Repository secrets** and add:

| Secret name | Value |
|---|---|
| `ORCAI_APP_ID` | The App ID from Step 2 |
| `ORCAI_APP_INSTALLATION_ID` | The Installation ID from Step 5 |
| `ORCAI_APP_PRIVATE_KEY` | The full PEM file content (including `-----BEGIN RSA PRIVATE KEY-----` header/footer lines) |

**Step 7 — Enable write permissions for GITHUB_TOKEN**

Go to **Settings → Actions → General → Workflow permissions** and select **"Read and write permissions"**. This allows the `orcai-run` workflow to push the automated lock-file commit back to the repository.
